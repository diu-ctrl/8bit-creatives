### Step 1.1 — Set explicit mobile height for `.hero-game-area`

In `styles.css`, find the mobile `.hero-game-area` rule (inside `@media (max-width: 767px)`).

**Before (current):**
```css

    padding: 12px 0 !important;
    width: 100% !important;
    max-width: 100% !important;
}
```

**After (fixed):**
```css
.hero-game-area {
    padding: 12px 0 !important;
    width: 100% !important;
    max-width: 100% !important;
    height: 200px !important;          /* matches canvas internal height — eliminates empty space */
}
```

**Why 200px:** The canvas internal height is 200px. Setting the container to exactly 200px means the canvas fills the container with 1:1 pixel mapping (no vertical scaling, no empty space, no distortion).

### Step 1.2 — Fix the canvas CSS on mobile

In the same mobile media query, find the `#heroDinoCanvas` rule.

**Before (current):**
```css
.hero-game-area canvas,
#heroDinoCanvas {
    width: 100% !important;
    max-width: 100% !important;
    height: auto !important;           /* ← BUG: calculates height from aspect ratio, making canvas too small */
    display: block !important;
}
```

**After (fixed):**
```css
.hero-game-area canvas,
#heroDinoCanvas {
    width: 100% !important;
    max-width: 100% !important;
    height: 100% !important;            /* ← fills the 200px container exactly */
    display: block !important;
}
```

**Why `height: 100%` instead of `height: auto`:** `height: auto` calculates the CSS height from the canvas's internal aspect ratio (600:200 = 3:1), giving a tiny 125px canvas on a 375px-wide screen. `height: 100%` makes the canvas fill the full 200px container height — the canvas now uses the full game area with no wasted space.

## PHASE 2 — Make canvas width responsive + add resize handler in `app.js`

### Step 2.1 — Replace the hardcoded canvas dimensions with responsive values

In `app.js`, find the `initHeroDinoGame()` function. At the top of the function, replace the hardcoded dimension setup:

**Before (current):**
```javascript
function initHeroDinoGame() {
  const canvas = document.getElementById('heroDinoCanvas');
  if (!canvas) return;
  const ctx = canvas.getContext('2d');

  // Mobile scale factor
  const isMobile = window.innerWidth < 768;
  const SCALE = isMobile ? 2 : 1;

  // Dimensions
  const W = canvas.width = isMobile ? 600 : 1200;
  const H = canvas.height = 200;
```

**After (fixed):**
```javascript
function initHeroDinoGame() {
  const canvas = document.getElementById('heroDinoCanvas');
  if (!canvas) return;
  const ctx = canvas.getContext('2d');

  // Mobile scale factor
  let isMobile = window.innerWidth < 768;
  let SCALE = isMobile ? 2 : 1;

  // Responsive dimensions — canvas internal width matches the display width
  // (eliminates non-integer scaling artifacts on pixel art)
  function resizeCanvas() {
    // Read the CSS display width of the canvas
    const displayWidth = canvas.clientWidth || canvas.offsetWidth || window.innerWidth;
    // Set the internal resolution to match the display width (1:1 pixel mapping)
    // For retina sharpness, multiply by devicePixelRatio (but cap at 2x to avoid memory issues on mobile)
    const dpr = Math.min(window.devicePixelRatio || 1, 2);
    canvas.width = Math.round(displayWidth * dpr);
    // Height stays at 200 * dpr for consistent game area
    canvas.height = 200 * dpr;
    // Update the game variables
    W = canvas.width;
    H = canvas.height;
    isMobile = window.innerWidth < 768;
    SCALE = isMobile ? 2 : 1;
    // Update ground position (proportional to new height)
    groundY = Math.round(H * 0.8);  // 80% of canvas height (was 160/200 = 80%)
  }

  // Dimensions — now responsive (declared with let so they can be updated)
  let W, H, groundY;
  resizeCanvas();  // initial sizing

  // Re-init on resize/orientation change (debounced to avoid excessive re-inits)
  let resizeTimer = null;
  window.addEventListener('resize', () => {
    clearTimeout(resizeTimer);
    resizeTimer = setTimeout(() => {
      const wasMobile = isMobile;
      resizeCanvas();
      // If mobile/desktop state changed, re-init the game with new physics
      if (wasMobile !== isMobile) {
        // Reset game state with new physics constants
        speed = isMobile ? 5.5 : 6.5;
        GRAVITY = isMobile ? 0.7 : 0.55;
        JUMP_VEL = isMobile ? -13.5 : -10.5;
        dino.x = isMobile ? 40 : 60;
        dino.w = Math.round(38 * SCALE);
        dino.h = Math.round(40 * SCALE);
      }
      // Clamp dino position to new dimensions
      dino.y = Math.min(dino.y, groundY);
    }, 250);
  });
  window.addEventListener('orientationchange', () => {
    setTimeout(() => {
      const wasMobile = isMobile;
      resizeCanvas();
      if (wasMobile !== isMobile) {
        speed = isMobile ? 5.5 : 6.5;
        GRAVITY = isMobile ? 0.7 : 0.55;
        JUMP_VEL = isMobile ? -13.5 : -10.5;
        dino.x = isMobile ? 40 : 60;
        dino.w = Math.round(38 * SCALE);
        dino.h = Math.round(40 * SCALE);
      }
      dino.y = Math.min(dino.y, groundY);
    }, 250);
  });
```

**Key changes:**

1. `W`, `H`, `groundY` are now declared with `let` (mutable) instead of `const` (immutable) — they can be updated on resize
2. `isMobile` and `SCALE` are now `let` — they can be updated on resize
3. `resizeCanvas()` function reads the actual CSS display width (`canvas.clientWidth`) and sets the canvas internal width to match (× `devicePixelRatio` for retina sharpness) — eliminates non-integer scaling
4. The canvas height is `200 * dpr` (proportional to the original 200px, but sharper on retina)
5. `groundY` is recalculated as 80% of the new `H` (matching the original 160/200 = 80% ratio)
6. A debounced resize handler (250ms) re-sizes the canvas when the user rotates or resizes the browser
7. If the mobile/desktop state changes (crossing the 768px breakpoint), the physics constants (speed, gravity, jump velocity) and dino dimensions are updated to match the new state
8. The dino's Y position is clamped to the new groundY to prevent it from being below the ground after resize

### Step 2.2 — Update all references to use the mutable variables

The game code uses `W`, `H`, `groundY`, `isMobile`, `SCALE`, `speed`, `GRAVITY`, `JUMP_VEL` throughout the function. Since they were originally `const`, they can't be reassigned.

After Step 2.1 changes them to `let`, verify that all references still work. The game logic (jump, spawn, collision, draw) uses these variables — they should all work with the new `let` declarations because the values are the same (just mutable now).

**Specifically, find and update these declarations (change `const` to `let`):**

```javascript

// After:

let GRAVITY = isMobile ? 0.7 : 0.55;
let JUMP_VEL = isMobile ? -13.5 : -10.5;
let DUCK_H = Math.round(23 * SCALE);

```

Also update the `dino` object to use `let`:
```javascript

// After:

```

And the obstacles/clouds arrays can stay `let` (they already are).

### Step 2.3 — Update the groundY calculation in resizeCanvas

In the `resizeCanvas()` function from Step 2.1, the groundY is calculated as:
```javascript
groundY = Math.round(H * 0.8);
```

On the original 200px canvas, groundY was 160 (= 200 × 0.8). On the new responsive canvas with `H = 200 * dpr`, groundY = `200 * dpr * 0.8`. For dpr=1: groundY=160 (same as before). For dpr=2 (retina): groundY=320 (double, but the canvas is also double — so the visual position is the same).

This is correct — the ground position scales proportionally with the canvas height.

### Step 2.4 — Update the dino Y position on resize

In the resize handler from Step 2.1, after resizing the canvas, clamp the dino's Y position:
```javascript
dino.y = Math.min(dino.y, groundY);
```

This prevents the dino from being stuck below the ground line after a resize.

Use Option B (cleaner).

Also update the text POSITION coordinates to scale with dpr:

```javascript
// In drawScore():

// High score:

// In drawGameOver():

// In drawWaiting():

```

This scales the text positions proportionally with the canvas's internal resolution, so the text appears at the same VISUAL position regardless of the dpr.
