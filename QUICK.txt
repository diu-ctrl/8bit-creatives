## PHASE 1 — Fix the auto-fall race condition in `app.js`

### Step 1.1 — Move `autoFallTriggered = true` to AFTER the successful detach

Find the `triggerAutoFall()` function (from Phase 0 Step 0.1). Restructure it so the flag is set ONLY after the character has been successfully detached.

**Before (buggy):**
```javascript
function triggerAutoFall() {
    if (autoFallTriggered) return;
    autoFallTriggered = true;

    const pickedCharG = pickRandomCharacter();
    if (!pickedCharG) return;

    const body = detachCharacter(pickedCharG);
    if (!body) return;

    // Respawn after fall completes...
    setTimeout(() => { ... }, 4000);
}
```

**After (fixed):**
```javascript
function triggerAutoFall() {
    if (autoFallTriggered) return;

    const pickedCharG = pickRandomCharacter();
    if (!pickedCharG) {
        // Characters not generated yet — retry in 500ms (up to 10 times)
        if (!triggerAutoFall._retries) triggerAutoFall._retries = 0;
        triggerAutoFall._retries++;
        if (triggerAutoFall._retries <= 10) {
          setTimeout(triggerAutoFall, 500);
        }
        return;
    }

    const body = detachCharacter(pickedCharG);
    if (!body) {
        // Detach failed — retry with a different character in 500ms (up to 5 times)
        if (!triggerAutoFall._detachRetries) triggerAutoFall._detachRetries = 0;
        triggerAutoFall._detachRetries++;
        if (triggerAutoFall._detachRetries <= 5) {
          setTimeout(triggerAutoFall, 500);
        }
        return;
    }

    // ONLY set the flag after the character has been successfully detached
    autoFallTriggered = true;

    // Respawn after fall completes so character returns to hanging position
    setTimeout(() => {
      if (body.isDragging) {
        const checkInterval = setInterval(() => {
          if (!body.isDragging) {
            clearInterval(checkInterval);
            setTimeout(() => respawnCharacter(pickedCharG, body), 2000);
          }
        }, 500);
        return;
      }
      respawnCharacter(pickedCharG, body);
    }, 4000);
}
```

**Key changes:**
1. `autoFallTriggered = true` is moved to AFTER `detachCharacter()` succeeds — the flag is only locked when a character actually falls
2. If `pickRandomCharacter()` returns null (SVG characters not generated yet), the function retries up to 10 times with 500ms delay — this handles the race condition where the IntersectionObserver fires before `buildEclipseCharacters()` has populated the SVG group
3. If `detachCharacter()` returns null (character already detached or element not found), the function retries up to 5 times with 500ms delay — this handles edge cases where the randomly picked character was already clicked by the user

## PHASE 3 — Add `content-visibility: auto` to off-screen sections in `index.html`

### Step 3.1 — Add `content-visibility: auto` CSS rules to the inline `<style>` block

In `index.html`, find the inline `<style>` block in the `<head>`. Add these rules at the END of the `<style>` block (before the closing `</style>` tag):

```css
/* === PERFORMANCE: Skip rendering off-screen sections === */
/* content-visibility: auto tells the browser "don't render this section's
   contents until it's near the viewport" — massive performance win
   for long-scrolling pages with many sections. */
.case-studies-section,
.services-section,
.esports-section,
.founders-section,
.cta-section {
  content-visibility: auto;
  contain-intrinsic-size: 800px;
}
/* === END PERFORMANCE === */
```

**Why this works:**

`content-visibility: auto` tells the browser: "Skip rendering this section's contents until the user scrolls near it." The browser reserves space for the section (using `contain-intrinsic-size: 800px` as the placeholder height) but doesn't actually paint the section's children, run its animations, or compute its layout until it's about to scroll into view.

This is a MASSIVE performance win for long-scrolling pages with many sections — the browser only does the heavy rendering work for sections the user can actually see.

**Zero visual impact:**
- The sections look IDENTICAL when scrolled into view
- The `contain-intrinsic-size: 800px` is just a placeholder height estimate — the actual section height is computed when it scrolls into view
- No animation changes, no design changes, no interaction changes

**Do NOT add `content-visibility: auto` to:**
- The hero section (it's above the fold — needs to render immediately)
- The about section (it has the Matter.js physics + auto-fall — needs to be ready when the user scrolls to it)
- The footer (it's simple enough to not need optimization)
